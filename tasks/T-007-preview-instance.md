## Spec
Set up the F5 preview loop under gitignored `gitea-root/`: official Gitea **1.27.3**
darwin-arm64 binary from `https://dl.gitea.com/gitea/` (verify the exact asset name in
the listing; nearest 1.27.x only if 1.27.3 is absent — log it), sqlite, no external
services.

## File ownership (do NOT touch anything else)
- `gitea-root/` (gitignored): `bin/`, `work/` (WORK_PATH + app.ini + db), `AUTH`,
  `README.md` (exact start/stop commands, credentials)
- `scripts/build.sh` — assembles `dist/theme-soppy-light.css` and
  `dist/theme-soppy-dark.css` by concatenation, in this order:
  `src/fonts.css` → meta-info block (heredoc per variant: display name "Soppy Light"/
  "Soppy Dark", color-scheme "light"/"dark") → `src/palette-light.css` or
  `src/palette-dark.css` → `src/components.css`. Idempotent, `set -euo pipefail`,
  mkdir -p dist.
- `scripts/sync-preview.sh` — run build.sh, then idempotently ensure symlinks:
  `gitea-root/work/custom/public/assets/css` → repo `dist/`,
  `gitea-root/work/custom/public/assets/soppy` → repo `assets/`. No Gitea restart
  needed after sync (custom assets are served from disk; theme list re-scans every
  second).

## Constraints
- app.ini: HTTP 127.0.0.1:6300, sqlite in work dir, `INSTALL_LOCK=true`, generated
  `SECRET_KEY`, `[ui] THEMES = gitea-auto,gitea-light,gitea-dark,soppy-light,soppy-dark`
  and `DEFAULT_THEME = soppy-dark`
- Create an admin user via `gitea admin user create` (record credentials ONLY in
  `gitea-root/AUTH`)
- Boot once to verify: `gitea --version`, then start, `curl -sI` the home page — check
  status 200 AND whether a Content-Security-Policy header would block
  fonts.googleapis.com / fonts.gstatic.com (log the finding; if CSP blocks, note the
  fallback: self-hosting Noto Serif SC). Then stop the server — orchestrator does the
  final launch.
- Do NOT modify anything under `/Users/soppylzz/code/reference/**`; do NOT run git.

(modules/public/public.go:26-32); `LayeredFS.Open`/`ReadFile` try the custom layer
first (modules/assetfs/layered.go:74-88), `ListFiles`/`ReadDir` merge names across
layers (layered.go:90-99,150-162). So any request served through
`public.FileHandlerFunc` (public.go:44, wired for `/assets/*`) is per-request
shadowable by `<CustomPath>/public/assets/<same path>`.

**(a) "favicon does not change" — verdict**: server side is correct and hash-proven;
the residual staleness is client-side caching. Evidence: `/favicon.ico` → 301 →
`/assets/img/favicon.png` → our PNG (456,458 B, sha256 matches `assets/favicon.png`);
`/assets/img/favicon.svg` → our wrapper (609,082 B, sha256 match). Mechanisms that
keep a browser showing the old icon: `/assets/*` is served with
`Cache-Control: public, max-age=21600` (6 h, observed on the wire), `/favicon.ico` is
a **301 permanent** (cached indefinitely), and browsers keep their own favicon cache
independent of HTTP cache. Fix is client-side: new tab / private window / clear
site+favicon data; verify the server by opening
`http://127.0.0.1:6300/assets/img/favicon.svg` directly.
